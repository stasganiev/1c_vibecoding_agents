# Завершение сессии

Переносишь из чата в файлы то, что переживёт эту сессию, и оставляешь репозиторий
в состоянии, из которого следующая сессия стартует без раскопок.

Сессия закрыта правильно, если следующая сессия, прочитав только память, понимает:
где остановились, что решено, что открыто и какой следующий шаг.

## Что переживает сессию, а что нет

**Записывай:** принятые решения и **их причины**; отменённые варианты и почему
(чтобы их не предлагали заново); изменения статуса проекта; протухшие факты и новые
факты об окружении; грабли с текстом ошибки.

**Не записывай:** пересказ диалога; то, что видно из кода и `git log`; промежуточные
рассуждения; то, что верно только внутри этой сессии.

Относительные даты переводи в абсолютные: не «на прошлой неделе», а «2026-09-02».

## Порядок

### 1. Разбери сессию
Пройди по чату и выпиши долгоживущее по критерию выше. Если решение отменяло
предыдущее — фиксируй **оба**: что было, что стало и почему.

### 2. Обнови память

Где память лежит — смотри `.claude/audit.config.json`: `memory_file` даёт общую,
`pairs` — где искать память проекта. Нет конфига — ориентируйся по репозиторию.

- **память проекта** — статус, решения, открытые вопросы. В этом воркспейсе
  `results/$Project/memory.local.md`.
- **общая память** — только то, что важно **вне** одного проекта: инструменты,
  общие грабли, межпроектные решения. Одна строка с датой, без пересказа.
  Здесь это `results/memory.md`.

Правь существующие записи, если они устарели, а не дописывай рядом противоречащую:
две версии одного факта хуже одной устаревшей — следующая сессия не поймёт, какая верна.

**Если репозиторий чужой и писать в него нельзя** (рабочий проект, где твои
файлы никому не нужны в истории) — память кладётся туда, куда указывает
`memory_file` в конфиге, хоть за пределы репозитория. Не создавай файлы в чужом
дереве по своему усмотрению.

### 3. Ревизия инструкций
Изменилось ли что-то, что делает инструкцию проекта неверной? Поправь.
Корневой `CLAUDE.md` трогай, только если решение касается всех проектов.

### 4. Личное о пользователе — в inbox, не напрямую
Всплыли личные факты (биография, навыки, цели, предпочтения)? **Не правь
файлы профиля руками.** Положи файл `about_me/inbox/YYYY-MM-DD_<тема>.md`,
его разберёт скилл `ingest-about-me`.

### 5. Аудит AI-инструментов — если они менялись
Триггер: в сессии создавались или правились файлы в `.claude/skills/`,
`.claude/commands/`, `.claude/agents/`, `.claude/hooks/`, `.claude/settings.json`
или `.mcp.json`.

Проверить (через `git status` / `git diff`, что реально менялось):

1. **Целостность** — `python .claude/skills/ai-tools-audit/scripts/audit.py`
   (не `python3`, см. ниже). Битые ссылки, расхождения в окружении, парность
   проектов, осиротевшие хуки, фронтматтер.
2. **Факты об окружении** — если скилл начал вызывать новый инструмент, впиши
   его в `env_facts` в `.claude/audit.config.json`, указав, **где** это заявлено.
   Без указания источника непонятно, что чинить, когда факт протухнет.
3. **Пути** — новые ссылки в скиллах ведут на существующие файлы. Скрипт проверит
   те, что от корня репо; относительные пути в скиллах он не проверяет — сверь глазами.
4. **Фактические утверждения** — если скилл заявляет «в системе есть/нет X»,
   проверь запуском, а не по памяти. Такие утверждения протухают молча.
5. **Описание скилла** — `description` во frontmatter отражает, что скилл делает
   сейчас, а не что задумывалось. По нему скилл находят, поэтому оно должно
   называть вход, выход и когда применять.
6. **Хуки** — если менялся хук, запусти его руками и убедись, что он не роняет
   сессию и не шумит на нормальном состоянии.

Результат аудита — строкой в отчёт. Если что-то поправил — записью в память.

### 6. Статистика сессии — всегда

```
python .claude/skills/ai-tools-audit/scripts/session_stats.py --append
```

Показывает, во что обошлась сессия, и дописывает строку в
`~/.claude/sessions_report.md` — общий журнал по всем проектам, лежит вне
репозиториев и в git не попадает.

Цифры бери из вывода, **не считай сам**: пик контекста, выход, чтение кеша,
число запросов, вызовы инструментов и скиллов.

**Токены по отдельным инструментам не раскладываются.** API отдаёт usage на
запрос целиком, а не на вызов инструмента. Если пользователь спросит «сколько
съел этот скилл» — так и скажи, не выдумывай цифру. Считается только число
вызовов.

Строку в память проекта пиши **только если есть что сказать**:
- сессия заметно дороже обычного — и понятно почему;
- впервые вызван скилл, которым раньше не пользовались;
- видно, что какой-то инструмент вызывается вхолостую.

Обычные цифры в память не переносятся: они уже в отчёте, а память — не журнал
расходов. Строка вида «пик 188k, выход 131k» не помогает следующей сессии
и стоит токенов в каждом запросе.

### 7. Отчёт пользователю
Структура как требует `CLAUDE.md`: что сделано / что нужно / что требуется от тебя /
следующий шаг. Плюс:
- какие файлы памяти обновлены и чем;
- что осталось нерешённым (явным списком, а не «есть вопросы»);
- результат аудита AI-инструментов, если он проводился;
- стоимость сессии одной строкой: пик контекста, выход, где смотреть подробности.

В конце — **ровно одно** предложение по автоматизации. Одно, а не список: список
никто не выполняет.

## Грабли этой машины

- **`python`, не `python3`** — `python3` в PATH указывает на заглушку Microsoft Store,
  которая молча ничего не выполняет.
- **Правка файлов через Python перезаписывает окончания строк в CRLF**, и git
  показывает файл целиком переписанным. После таких правок нормализуй:
  `data.replace(b'\r\n', b'\n')` в бинарном режиме.

## Чего не делать

- Не коммить без явной просьбы пользователя.
- Не переписывать файлы профиля напрямую — только через inbox.
- Не писать в исходные папки проектов ничего, кроме правок инструкций:
  рабочие артефакты идут в папку результатов (здесь — `results/`).
- Не дублировать в общей памяти то, что уже есть в памяти проекта.
- Не переносить обычные цифры по токенам в память: они уже в отчёте по сессиям.
- Не оставлять в памяти два противоречащих утверждения об одном факте.
