# Аудит AI-инструментов

Проверяет, что инструменты репозитория исправны: скиллы находятся, хуки
запускаются, ссылки ведут на существующие файлы, а вызываемые программы есть
в системе.

Скилл переносится в любой репозиторий копированием папки. Знаний о структуре
конкретного проекта в нём нет — то, что нельзя определить автоматически,
задаётся необязательным конфигом.

## Запуск

```
python .claude/skills/ai-tools-audit/scripts/audit.py
```

| Флаг | Зачем |
|---|---|
| `--quiet` | молчит, если чисто — режим для хуков |
| `--json` | машинный вывод |
| `--root PATH` | аудит другого репозитория |
| `--init` | создать заготовку конфига по структуре репозитория |
| `--force` | перезаписать существующий конфиг при `--init` |

Код возврата: `0` — чисто, `1` — есть замечания. Скрипт никогда не бросает
исключение наружу: сломанный аудит не должен блокировать работу.

## Что проверяется без всякой настройки

1. **Инвентарь** — сколько скиллов своих и вендорных, агентов, команд, хуков.
2. **Фронтматтер** — обязательные поля `name` и `description`, совпадение
   `name` с именем папки, дубли имён, слишком длинные описания.
3. **Хуки** — файл на месте, синтаксис цел, нет забытых на диске и не
   подключённых в `settings.json`.
   **MCP** — в `.mcp.json` пути `command` и `args` абсолютные и существуют,
   команда есть в PATH. Stdio-сервер стартует из папки сессии, поле `cwd`
   Claude Code не применяет: относительный путь даёт в `/mcp` только
   CONNECTION_CLOSED без причины. Значения `env` не читаются.
4. **Ссылки** — пути в `.md`-файлах инструментов ведут на существующие файлы.
5. **Окружение** — программы, вызываемые в скиллах (`python`, `node`,
   `ffmpeg`, …), реально доступны.

Вендорные скиллы из проверок 2–5 исключаются: чинить чужое нельзя, а шумят
они за всех сразу. Определяются по lock-файлам, префиксу в `name`, служебным
файлам внутри папки и по тому, добавлены ли пачкой в одном коммите.

## Конфиг — только для того, что нельзя угадать

Необязательный `.claude/audit.config.json`. Без него работают проверки 1–5.

```json
{
  "pairs": [["projects", "results"]],
  "pair_required_files": {"results": ["memory.local.md"]},
  "memory_file": "results/memory.md",
  "link_roots": ["projects", "results", "about_me"],
  "env_tools": {"python": "python --version"},
  "ignore_skills": []
}
```

| Ключ | Что задаёт |
|---|---|
| `pairs` | папки, подпапки которых должны соответствовать друг другу |
| `pair_required_files` | файлы, обязательные внутри каждой подпапки |
| `memory_file` | файл общей памяти, наличие которого проверяется |
| `link_roots` | корни ссылок; пусто — берутся папки верхнего уровня |
| `env_tools` | инструменты и команды проверки; пусто — определяются сами |
| `env_facts` | факты об окружении с указанием, **где** заявлены |
| `known_missing` | ссылки, которых заведомо нет, с обязательной причиной |
| `require_mention_in_memory` | требовать упоминания каждого проекта в памяти |
| `project_root` | папка задач, если структура без пары: `projects/tasks` |
| `project_memory` | имя файла памяти внутри папки задачи |
| `project_instruction` | имя файла инструкции внутри папки задачи |
| `ignore_skills` | что не аудировать |

Задавай только то, что отличается от догадок скрипта. Пустой конфиг
эквивалентен его отсутствию.

### Заготовку делает `--init`

```
python .claude/skills/ai-tools-audit/scripts/audit.py --init
```

Смотрит на репозиторий и пишет `.claude/audit.config.json` по тому, что нашёл:

- **пара папок** — две папки верхнего уровня с пересекающимися подпапками
  (`projects/` + `results/`);
- **папка задач** — однотипные подпапки, у большинства которых есть файл
  памяти (`projects/tasks/FT-xxx/`);
- **общая память** — `memory.md` или `memory.local.md` в корне либо в папке
  результатов;
- **инструменты** — что вызывается в своих скиллах, заготовкой для `env_facts`.

Не найдено ничего специфичного — пишет пустой конфиг, и это верный результат:
базовых проверок хватает.

**Заготовку нужно проверить.** Она построена на догадках, а не на твоих
правилах. Особенно поля `where` в `env_facts`: там стоит заглушка
«УКАЖИ, где это заявлено» — источник знает только человек, а без него
непонятно, что чинить, когда факт протухнет.

Существующий конфиг `--init` не трогает: скажет, что он есть, и предложит
`--force`.

## Порядок работы

### 1. Прогони аудит
Запусти скрипт. Если замечаний нет — скажи об этом одной строкой и переходи
к шагу 4.

### 2. Разбери замечания
Не чини всё подряд. Раздели на три группы и покажи их пользователю:

- **Поломка** — битая ссылка, несуществующий инструмент, ошибка синтаксиса.
  Чини сразу.
- **Небрежность** — длинное описание, `name` не совпадает с папкой.
  Предложи правку, но спроси.
- **Решение пользователя** — осиротевший хук, лишний скилл. Не трогай,
  только доложи: удалять или подключать — не твой выбор.

### 3. Чини поломки
После правок прогони аудит ещё раз — правка могла создать новую поломку.

### 4. Проверь то, что скрипт не видит
Скрипт не читает смысл. Глазами проверь то, что менялось в этой сессии:

- **Фактические утверждения в скиллах.** «В системе нет Python», «файл лежит
  там-то» — устаревает молча. Такие фразы стоят дорого: следующая сессия
  им поверит.
- **Описание скилла.** Оно решает, вызовется скилл или нет. Проверь, что в нём
  есть слова, которыми пользователь реально попросит эту работу.
- **Конфиг.** Если структура репозитория изменилась — обнови
  `audit.config.json`.

### 5. Доложи
Что нашлось, что починено, что оставлено на решение пользователя. Без
пересказа вывода скрипта — только итог и то, что требует ответа.

## Стоимость сессии

```
python .claude/skills/ai-tools-audit/scripts/session_stats.py
python .claude/skills/ai-tools-audit/scripts/session_stats.py --append
```

Во что обошлась сессия: пик контекста, выход, экономия на кеше, число запросов,
вызовы инструментов и скиллов. Источник — транскрипт самого Claude Code, а не
оценка. С `--append` дописывает строку в `~/.claude/sessions_report.md` — журнал
по всем проектам вне репозиториев.

Без флагов считается **текущая** сессия — та, из которой скрипт запущен
(по `CLAUDE_CODE_SESSION_ID`). Указывать `--session` при завершении не нужно.
Если транскрипта текущей сессии в проекте нет, скрипт скажет об этом вслух
и возьмёт последнюю по времени.

Флаги: `--all` — все сессии проекта, `--session ID` — конкретная,
`--last` — последняя по времени вместо текущей, `--json`.

**Токены по отдельным инструментам не раскладываются.** API отдаёт usage на
запрос целиком, а не на вызов инструмента: результат вызова просто вливается
в контекст следующего запроса. Считается только число вызовов — и это честно,
в отличие от любой цифры «этот скилл съел N токенов».

## Бюджет контекста

```
python .claude/skills/ai-tools-audit/scripts/token_budget.py
```

Показывает, сколько токенов стоит стартовый контекст и из чего складывается.
Считает все слои, а не только скиллы репозитория: описания из `~/.claude/skills/`
и плагинов едут в контексте так же, но видны во всех проектах сразу.

Флаги: `--api` — точный подсчёт через `count_tokens` (нужен ключ Anthropic
и пакет `anthropic`), `--root PATH` — другой репозиторий, `--top N` — длина
списка тяжёлых описаний, `--window N` — окно модели (по умолчанию 1M),
`--budget-chars N` — бюджет списка скиллов вручную.

**Потолок списка скиллов.** Claude Code отдаёт модели список скиллов не
длиннее доли окна (`skillListingBudgetFraction`, 1%) и режет каждое описание
до `skillListingMaxDescChars` (1536). При переполнении описания теряют реже
всего вызываемые: имя остаётся, но по смыслу запроса скилл почти не
срабатывает. Скрипт читает `skillOverrides`, эти настройки и лог вызовов
и показывает, кто останется без описания. Бюджет откалиброван по одному
замеру, сверяй с `/context`.

Без `--api` считает по символам с поправкой на кириллицу. Пропорции верны,
абсолют приблизителен — для решения «резать или нет» этого достаточно.

## Мониторинг использования

```
python .claude/skills/ai-tools-audit/scripts/usage_report.py
python .claude/skills/ai-tools-audit/scripts/usage_report.py --unused
```

Отвечает на вопрос «чем я реально пользуюсь» — тот, без которого нельзя
решать, что удалять. Данные собирает хук
`~/.claude/hooks/skill-usage-logger.js`, подключённый глобально: он видит
вызовы во **всех** проектах и пишет в `~/.claude/skill_usage.jsonl` — вне
репозиториев, поэтому ни в один git не попадает.

Логируются вызовы скиллов, slash-команд, субагентов и итог каждой сессии
с **реальными** токенами из транскрипта (не оценкой).

Флаги: `--days N` — период, `--project ИМЯ` — один проект, `--unused` —
что установлено, но ни разу не вызывалось.

**Не делай выводов раньше двух недель наблюдения.** Пустой раздел
«не вызывались» на второй день означает нехватку данных, а не ненужность
инструментов.

## Перенос в другой репозиторий

Скопировать папку `.claude/skills/ai-tools-audit/`. Всё.

Если в новом репозитории есть структурные соглашения (парные папки,
обязательные файлы) — сгенерировать конфиг через `--init` и проверить его.
Если нет — скилл работает как есть.

Для запуска при старте сессии — повесить на `SessionStart` с `--quiet`:
хук промолчит, если всё чисто, и напечатает замечания, если нет.
